# BWK009: Cookie is readable by scripts

| | |
|---|---|
| Category | Security |
| Severity | Warning |
| Weakness | [CWE-1004](https://cwe.mitre.org/data/definitions/1004.html): Sensitive cookie without 'HttpOnly' flag |

## Cause

`HttpOnly = false` on a `CookieBuilder`: the `Cookie` options of cookie authentication, session, antiforgery or TempData. Assignments inside an `IsDevelopment()` check are not reported.

## Why it matters

These cookies carry the session or the antiforgery secret, and the browser sends them automatically, so JavaScript never needs to read them. With `HttpOnly = false`, any script that runs on the page, including one injected through a cross-site scripting flaw, can read the cookie and use the session from somewhere else.

## How to fix

Remove the line; `HttpOnly` is `true` by default for these cookies.

If a single-page app needs to read the antiforgery request token, send it in a separate cookie with `Response.Cookies.Append` and leave the antiforgery cookie itself `HttpOnly`, as the [SPA section of the CSRF docs](https://learn.microsoft.com/aspnet/core/security/anti-request-forgery#antiforgery-with-javascript) shows.

## When to suppress

When the cookie holds nothing sensitive. In that case it probably does not need a `CookieBuilder` from the framework either.
