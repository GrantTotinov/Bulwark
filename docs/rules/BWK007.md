# BWK007: MCP endpoint is mapped without authorization

| | |
|---|---|
| Category | Security |
| Severity | Warning |
| Weakness | [CWE-306](https://cwe.mitre.org/data/definitions/306.html): Missing authentication for critical function |

## Cause

`MapMcp()` from `ModelContextProtocol.AspNetCore` is called, and none of these protect it:

- `.RequireAuthorization(...)` or `.AllowAnonymous()` on the `MapMcp()` call;
- `.RequireAuthorization(...)` on the route group it is mapped on;
- a fallback authorization policy (`AuthorizationOptions.FallbackPolicy` or `AddAuthorizationBuilder().SetFallbackPolicy(...)`) anywhere in the project;
- `AddAuthorizationFilters()` on the MCP server builder, which enables `[Authorize]` on tools.

## Why it matters

An MCP server exists so that clients can list and call its tools, and tools usually read data or do things: query a database, send email, change records. Over HTTP, anyone who can reach the URL is a client. Scans of internet-facing MCP servers keep finding a large share that expose tools with no authentication at all.

The MCP C# SDK maps the endpoint without any authorization metadata. The SDK documentation recommends doing authorization in ASP.NET Core, not inside each tool.

## How to fix

```csharp
builder.Services.AddAuthentication().AddJwtBearer();
builder.Services.AddAuthorization();
builder.Services.AddMcpServer().WithHttpTransport().WithToolsFromAssembly();

var app = builder.Build();
app.MapMcp().RequireAuthorization();
```

For per-tool rules, call `AddAuthorizationFilters()` on the MCP server builder and put `[Authorize]` on the tools.

If the server really is meant to be public, for example a documentation search, say so in code:

```csharp
app.MapMcp().AllowAnonymous();
```

## When to suppress

When something outside the app, such as an API gateway, authenticates every request to the MCP route. Prefer `.AllowAnonymous()` with a comment, which documents the decision where the endpoint is mapped.
