# BWK005: JWT signature validation is disabled

| | |
|---|---|
| Category | Security |
| Severity | Warning |
| Weakness | [CWE-347](https://cwe.mitre.org/data/definitions/347.html): Improper verification of cryptographic signature |

## Cause

`TokenValidationParameters` is configured so that a token's signature is not checked:

- `RequireSignedTokens = false`, or
- a `SignatureValidator` lambda that only parses the token: it calls nothing, or only `Read*` methods such as `ReadJwtToken`. For example `SignatureValidator = (token, _) => new JsonWebToken(token)`.

## Why it matters

The signature is what proves the token came from the issuer. Without it, anyone can write a token with any claims (`sub`, `role`, `exp`) and the app accepts it. `RequireSignedTokens = false` accepts unsigned tokens (`alg: none`). A `SignatureValidator` that only parses replaces the real check with nothing. Both usually start as a workaround for a key configuration error and stay.

## How to fix

Remove the setting and give the handler the issuer's keys, usually through `Authority` (keys are read from the issuer's metadata) or `IssuerSigningKey`:

```csharp
builder.Services.AddAuthentication().AddJwtBearer(o =>
{
    o.Authority = "https://login.example.com";
    o.Audience = "api://my-api";
});
```

## When to suppress

When the token's integrity is guaranteed another way before it reaches the handler, and you can explain it in the justification. That is rare.

## Not in this rule

`ValidateIssuer`, `ValidateAudience`, `ValidateLifetime` and `RequireExpirationTime = false` are covered by the built-in rule [CA5404](https://learn.microsoft.com/dotnet/fundamentals/code-analysis/quality-rules/ca5404), which is off by default. Turn it on in `.editorconfig`: `dotnet_diagnostic.CA5404.severity = warning`.
