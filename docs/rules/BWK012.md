# BWK012: Passkey relying party ID comes from the Host header

| | |
|---|---|
| Category | Security |
| Severity | Info |
| Weakness | [CWE-346](https://cwe.mitre.org/data/definitions/346.html): Origin validation error |

## Cause

The app calls `SignInManager.MakePasskeyCreationOptionsAsync` or `MakePasskeyRequestOptionsAsync` (ASP.NET Core Identity passkeys, .NET 10 and later), and nothing in the project sets `IdentityPasskeyOptions.ServerDomain`.

The Blazor Web App template with Individual Accounts is reported, because it does not set `ServerDomain`.

## Why it matters

The relying party ID is the domain a passkey belongs to. When `ServerDomain` is `null`, Identity takes it from the request's `Host` header. The [passkey documentation](https://learn.microsoft.com/aspnet/core/security/authentication/passkeys/#security-considerations) says the hosting environment must then validate host headers "to prevent credential-scoping attacks", or the app must set `ServerDomain`.

The default `"AllowedHosts": "*"` in `appsettings.json` does not validate anything.

The severity is Info because host validation can happen where the analyzer cannot see it: in `AllowedHosts` configuration, a reverse proxy or the hosting platform.

## How to fix

```csharp
builder.Services.Configure<IdentityPasskeyOptions>(o =>
{
    o.ServerDomain = "example.com";
});
```

Or restrict `AllowedHosts` to your host names, and suppress this rule.

## When to suppress

When the host is validated outside the code: `AllowedHosts` lists your domains, or the proxy or platform only forwards requests for them.
