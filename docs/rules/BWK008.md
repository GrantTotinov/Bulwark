# BWK008: Cookie can be sent over HTTP

| | |
|---|---|
| Category | Security |
| Severity | Warning |
| Weakness | [CWE-614](https://cwe.mitre.org/data/definitions/614.html): Sensitive cookie in HTTPS session without 'Secure' attribute |

## Cause

`SecurePolicy = CookieSecurePolicy.None` on a `CookieBuilder`: the `Cookie` options of cookie authentication, session, antiforgery or TempData. Assignments inside an `IsDevelopment()` check are not reported.

## Why it matters

Without the `Secure` attribute, the browser also sends the cookie over plain HTTP: after a downgrade, a mistyped `http://` link or a request to an HTTP-only subdomain. Anyone on the network path can read it there. For an authentication or session cookie, that is the user's session.

The built-in rules CA5382 and CA5383 check `CookieOptions.Secure` when calling `Response.Cookies.Append`, not the `CookieBuilder` options that the framework's own cookies use.

## How to fix

```csharp
builder.Services.AddAuthentication().AddCookie(o =>
{
    o.Cookie.SecurePolicy = CookieSecurePolicy.Always;
});
```

`CookieSecurePolicy.SameAsRequest`, the default for some cookies, also drops `Secure` when TLS ends at a proxy and the app sees HTTP. `Always` avoids that.

## When to suppress

When the app is only ever served over HTTP on a closed network. Then the cookie is exposed either way, and the fix is HTTPS.
