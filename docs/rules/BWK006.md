# BWK006: Identity provider metadata may be fetched over HTTP

| | |
|---|---|
| Category | Security |
| Severity | Warning |
| Weakness | [CWE-319](https://cwe.mitre.org/data/definitions/319.html): Cleartext transmission of sensitive information |

## Cause

`RequireHttpsMetadata = false` on `JwtBearerOptions`, `OpenIdConnectOptions` or another handler with the same property, outside an `if (....IsDevelopment())` block.

## Why it matters

The handler downloads the identity provider's metadata, including the keys it uses to check token signatures. With `RequireHttpsMetadata = false`, an `http://` authority or metadata address is accepted. Anyone who can intercept that request can serve their own keys, and the app then accepts tokens they sign.

If the authority is already `https://`, the setting does nothing, and removing it keeps it that way when someone changes the address later.

## How to fix

Remove the line, or limit it to development:

```csharp
builder.Services.AddAuthentication().AddJwtBearer(o =>
{
    o.Authority = builder.Configuration["Auth:Authority"];
    o.RequireHttpsMetadata = !builder.Environment.IsDevelopment();
});
```

Inside a container network, prefer HTTPS between the app and the identity provider over turning the check off.

## When to suppress

When the metadata address is plain HTTP inside a network you trust and HTTPS is not possible. Write down why in the justification.
