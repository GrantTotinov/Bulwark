# BWK001: CORS policy allows credentials from any origin

| | |
|---|---|
| Category | Security |
| Severity | Warning |
| Weakness | [CWE-942](https://cwe.mitre.org/data/definitions/942.html): Permissive cross-domain policy with untrusted domains |
| Benchmark | [R07](https://github.com/GrantTotinov/aspnetcore-security-bench/tree/main/rules/R07-cors-any-origin-credentials) |

## Cause

A CORS policy calls `AllowCredentials()` and also accepts every origin, through one of:

- `SetIsOriginAllowed(_ => true)`, or any lambda that always returns `true`;
- `AllowAnyOrigin()`;
- `WithOrigins("*")`.

The calls count as one policy when they are in one chain or on the same policy builder variable or lambda parameter.

## Why it matters

With credentials allowed, the browser sends the user's cookies on cross-origin requests and lets the calling page read the response. If every origin is allowed, any website the user visits can call the app as that user and read the result: profile data, tokens, anything the API returns.

ASP.NET Core refuses `AllowAnyOrigin()` together with `AllowCredentials()`. `SetIsOriginAllowed(_ => true)` gets around that check: the middleware echoes the request's origin in `Access-Control-Allow-Origin` and adds `Access-Control-Allow-Credentials: true`. The [ASP.NET Core CORS docs](https://learn.microsoft.com/aspnet/core/security/cors#set-the-allowed-origins) call both combinations insecure.

## How to fix

List the origins that may send credentials:

```csharp
// Before
builder.Services.AddCors(o => o.AddDefaultPolicy(policy => policy
    .SetIsOriginAllowed(_ => true)
    .AllowCredentials()));

// After
builder.Services.AddCors(o => o.AddDefaultPolicy(policy => policy
    .WithOrigins("https://app.example.com")
    .AllowCredentials()));
```

For many subdomains, use `WithOrigins("https://*.example.com").SetIsOriginAllowedToAllowWildcardSubdomains()`. If the API does not use cookies, remove `AllowCredentials()`.

## When to suppress

Almost never. A predicate that really does allow every origin with credentials is the vulnerability. If the app has no cookies or other ambient credentials at all, remove `AllowCredentials()` instead of suppressing.
