# BWK003: Form-bound endpoint skips antiforgery through HTTP method override

| | |
|---|---|
| Category | Security |
| Severity | Warning |
| Weakness | [CWE-352](https://cwe.mitre.org/data/definitions/352.html): Cross-site request forgery |
| Benchmark | [R01](https://github.com/GrantTotinov/aspnetcore-security-bench/tree/main/rules/R01-method-override-antiforgery) |

## Cause

The project sets `HttpMethodOverrideOptions.FormFieldName`, and a `MapDelete` endpoint binds form data (a `[FromForm]` parameter, `IFormFile`, `IFormFileCollection` or `IFormCollection`) without validating the antiforgery token itself.

## Why it matters

Form-field method override lets an HTML form send a DELETE: a POST with `_method=DELETE` is rewritten before routing. Because the endpoint binds form data, it carries antiforgery metadata, but `UseAntiforgery()` validates only POST, PUT and PATCH. The rewritten request is a DELETE, so the token is never checked, and a cross-site form can call the endpoint. A plain POST to the app is still rejected without a token, which makes the gap easy to miss in testing.

The [ASP.NET Core CSRF docs](https://learn.microsoft.com/aspnet/core/security/anti-request-forgery) describe this interaction.

## How to fix

Validate the token in the handler:

```csharp
app.MapDelete("/items/{id:int}", async (int id, [FromForm] string? note,
    IAntiforgery antiforgery, HttpContext context) =>
{
    if (!await antiforgery.IsRequestValidAsync(context))
    {
        return Results.BadRequest();
    }

    return Results.Ok();
});
```

Or do not bind form data on DELETE endpoints, or use header-based override (`UseHttpMethodOverride()` without a `FormFieldName`), which a cross-site form cannot set.

## When to suppress

When the endpoint is protected another way the rule cannot see, for example a filter that validates the token. `.DisableAntiforgery()` on the endpoint is treated as an explicit decision and not reported.

## Limits

Only `MapDelete` is checked. Endpoints mapped with `MapMethods` and other verbs are not.
